# Login hang after last-login accounting

Native login could authenticate and print `Last login`, then spin indefinitely
before starting the shell. A disposable copy of the persistent native image
reproduced the failure with both the original kernel and a rebuilt production
kernel. The guest was repeatedly faulting on a supervisor copy during `pwrite`
to the last-login database.

The filesystem uses 16 KiB blocks while RVM has 64 KiB VM pages. A sparse page
may have backing allocated for the current write but holes elsewhere, leaving
`PG_RDONLY` set. `ubc_fault_page` removed write permission from that kernel
window even for a write whose blocks the caller had already allocated. Fault
resolution returned success with a read-only mapping, and the same store
faulted again.

UBC now permits the allocated write range through its kernel window. Read
operations retain the previous protection checks. `PG_RDONLY` remains set,
and other mappings, including read-only user mappings, remain protected.

The new native FFS regression writes one 16 KiB block into a sparse 64 KiB
page, synchronizes and reopens the file, overwrites the block while a shared
read-only user mapping exists, checks file size and hole contents, and checks
that a child attempting to write that user mapping still receives SIGSEGV.
It runs on a freshly generated disposable filesystem:

```sh
python3 sys/arch/rvm/tests/native_init.py \
    --objdir obj.rvm-native-clean \
    --fixture-tree obj.rvm-native-clean/fixture-tree \
    --kernel-objdir obj.rvm-native-clean/kernel \
    --ffs --tmpfs --timeout 300
```

Repeated authenticated-login tests use disposable copies of the existing disk,
preserving the account databases and filesystem layout that exposed the hang:

```sh
python3 sys/arch/rvm/tests/native_root.py \
    --objdir obj.rvm-native-bit-ops \
    --kernel-objdir obj.rvm-native-clean/kernel \
    --login --login-count 5 --timeout 360
```

The runtime image can be updated by replacing its kernel and loader only.
Repackaging `root-native.img` would reset guest accounts and files and is not
needed for this fix.

Validation passed five authenticated logins at 64 MiB and three at 640 MiB
against copies of the previously failing disk. The FFS regression, tmpfs
mapping/accounting tests, native shell pipelines and init/getty startup also
passed. The integration driver uses the current native `cat` when available,
so the native shell's pipeline test does not accidentally run a bootstrap
binary left in an older exported fixture.
