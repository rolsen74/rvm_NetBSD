# GCC CPU flag support and clean native rebuild

The installed NetBSD GCC supports the CPU's implemented SR flag operations
and interrupt enable/disable operations. The maintained GCC sources contain
the changes; `sys/arch/rvm/stand/toolchain/rvm-status-flags.patch` retains them
after the empty-register-save-frame patch. The compiler and source backups are
in `/tmp/rvm-sr-flags/backup-installed/`.

Use `__builtin_rvm_clrc()` / `__builtin_rvm_setc()` for C, and the same names
with `v`, `z`, `n`, or `x` for the other arithmetic flags. Ignoring the result
emits just the flag opcode. Using the result returns an `unsigned long` SR
snapshot captured immediately after the opcode, as one compiler instruction.
For example:

```c
__builtin_rvm_clrc();
unsigned long sr = __builtin_rvm_setx();
```

The snapshot uses privileged `mfctrl sr`; only the write-only arithmetic
flag operations are usable in user mode. Intervening C expressions can change
live arithmetic flags, so inspect the returned snapshot rather than relying
on flags surviving arbitrary C code.

`__builtin_rvm_clri()` / `__builtin_rvm_seti()` change only the interrupt-enable
bit and return CR when their result is used. `__builtin_rvm_get_sr()` and
`__builtin_rvm_get_cr()` explicitly read the respective control registers.
These operations require supervisor mode. `__builtin_rvm_clrs()` returns void
and leaves supervisor mode; it requires an already prepared user context.
There is no SETS builtin because opcode 0x0079 is reserved.

The kernel now uses the SETI builtin in its interrupt-enable path. The assembly
disable helpers return the original CR and execute CLRI, replacing their old
copy/mask/control-register-write sequence. The ABI remains unchanged: arguments
R2-R9 are passed in registers, with eight caller-provided argument-home slots.

The clean native build is in `obj.rvm-native-sr-flags/`. It contains the kernel,
libc/csu, libm, libutil, libterminfo, libedit, libcrypt, libprop, and all 28 program
binaries from `make_native_root.py`, plus their command aliases. It is the
supported static native image, rather than a complete NetBSD release build.
A fresh-object-directory bug in `build_userland.py` was also fixed: libc and
csu object directories must exist before BSD make visits those libraries.

The separate fresh image can be launched using the normal launcher:

```sh
RVM_NATIVE_OBJDIR=obj.rvm-native-sr-flags ./run.sh
```

The default launcher's existing disk retains its account databases and files;
only its kernel and loader are updated after login validation. The fresh image
is separate and uses the test account database supplied to the clean build.

Validation passed the GCC runtime/output suite at `-O0`, `-O2`, `-Os`, and
`-O2 -fno-omit-frame-pointer`; the EARLY kernel's full boot checks at 64 and
640 MiB; two authenticated root logins with shell commands and logout on the
freshly rebuilt image at 640 MiB; and two more on a disposable copy of the
existing guest disk with the new kernel at 64 MiB. The default kernel and
loader were then updated with `.before-status-flags` backups. The existing
guest disk checksum remained unchanged.
