# RVM bootstrap libc progress — 2026-11-08

This records the earlier bootstrap milestone. The later
[stdio and native-shell update](rvm-stdio-shell-2026-11-08.md) supersedes the
limitations below concerning FILE streams, locale and `/bin/sh`.

The FFS root image now runs more unmodified NetBSD userland code. This extends
the [console/runtime milestone](rvm-console-userland-2026-11-08.md); it is still
a static bootstrap runtime, not the full NetBSD libc build or distribution.

## Library code

`stand/user/build.py` compiles the existing NetBSD sources for malloc, calloc,
realloc, free, posix_memalign, environment variables, atexit and DSO finalization,
execvp/execvpe, getpagesize, progname, red-black trees and memory/string routines.
The allocator is NetBSD's alternate `lib/libc/stdlib/malloc.c` (phkmalloc),
not its default jemalloc. These objects use the single-threaded paths;
allocator environment options gated on `_LIBC` are not enabled.

The RVM glue supplies native syscall wrappers, errno, a precise byte-valued
brk/sbrk and static startup. The kernel rounds break mappings to 64 KiB pages.
`getpagesize()` obtains the actual size through NetBSD sysctl. A final `end.o`
marks the end of static data, and sbrk initializes its floor at the next page.
Link order is crt0.o, application objects, librvm.a, then end.o. The standalone
builder and disk-root image builder arrange this automatically.

Returning from main calls exit, which finalizes registered handlers and then
invokes the optional cleanup hook before the native exit syscall. `_exit` and
`_Exit` bypass handlers. There are no FILE streams or buffered stdio yet;
puts writes directly to the descriptor. abort currently sends SIGABRT and
falls back to `_exit`; full signal-disposition handling remains future work.

The assembly adapter preserves copyright/revision strings in read-only data
because FHR assembly has no ELF metadata section stack. The original NetBSD
utility and libc source files remain unchanged.

## Programs and console

The image includes unchanged NetBSD `/bin/sync` and `/usr/bin/yes`. The C
monitor initializes PATH to `/bin:/usr/bin` and TERM to `dumb` when absent.
It supports env, set NAME VALUE, unset NAME and PATH lookup for run:

```text
rvm# env
rvm# set DEMO Ready
rvm# run sync
rvm# run yes hello
```

Ctrl-C terminates the foreground yes process and returns to the monitor.
The monitor is PID 1 and shares the foreground process group with its children;
this does not implement shell job control. It remains a simple command parser
without quoting, redirection or pipelines. Full stdio, locale, TLS, pthreads,
constructors, libc/csu build integration and a real shell remain to be ported.

## Checks

The disk-loaded runtime check exercises break growth/shrink, overflow rejection,
allocation sizes around page boundaries, zeroed calloc, realloc preservation,
1024 small allocations, 64 KiB alignment and heap isolation across fork/COW.
It checks setenv overwrite rules, putenv reference semantics, environment growth
and deletion, DSO-specific finalization, and dynamically allocated/reentrant
exit callbacks in reverse registration order. An unchanged yes producer writes
to a pipe and dies from SIGPIPE when the consumer closes it.

The SDL keyboard test checks environment changes, PATH-based sync execution,
Ctrl-C delivery to yes, PID 1 survival, file reads and failed-exec recovery.
Its pixel mode still checks that Backspace restores the rendered image.
Tests copy root images before use and reboot the same copy to verify FFS
persistence.

```sh
./build-diskroot.sh
python3 sys/arch/rvm/tests/hardfile.py --objdir obj.rvm-diskroot --diskroot
python3 sys/arch/rvm/tests/console.py --pixels
python3 sys/arch/rvm/tests/console.py --ram-mib 640
./run-diskroot.sh
```

Normal, GENERIC and DIAGNOSTIC disk-root builds passed the runtime checks
and persistence reboot at both 64 MiB and 640 MiB. SDL console tests passed
on all three configurations, with normal-kernel pixel checks at 64 MiB and
an additional normal console run at 640 MiB. The no-disk boot, raw disk
read/write and read-only tests passed at both sizes. Static-tool symbol,
archive and alignment tests and the VMEmu modifier-key unit test also passed.
