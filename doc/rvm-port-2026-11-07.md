# RVM porting session, 2026-11-07

This session advances the standalone NetBSD/RVM bootstrap. It does not yet
enter `kern/init_main.c:main()` or run user processes.

## Changes

- Generic MI slow software interrupts, with four guarded LWP stacks, FIFO
  queues, priority selection, coalescing, rescheduling and checked teardown.
- Optional real softclock LWP, with hardclock-to-softint callout delivery and
  CV wakeups, including dispatch while ordinary preemption is disabled.
- Corrected GCC caller homes, outgoing frame space, narrow argument padding
  and incoming varargs spills. Assembly C-call boundaries support the new ABI.
- NetBSD's unchanged MI format parser and snprintf bodies, selected by the
  corrected compiler ABI, with console/panic wrappers.
- Managed kernel aliases, per-page reverse mappings, sticky hardware R/M
  history, wired/unwired entries, page-wide protection and IRQ-safe updates.
- Kernel `kcopy()` with checked MMU exception return, overlap handling,
  preserved registers and restoration of a previous PCB fault handler.
- FHR linker undefined-symbol diagnostics now use BFD's debug-information
  fallback callbacks instead of calling null function pointers.

The source patches and reproduction instructions are in
`sys/arch/rvm/stand/toolchain/`. The maintained sibling `rvm_gcc` sources and
installed NetBSD-target cc1/lto1/ld were updated. Backups are under
`/tmp/rvm-netbsd-toolchain-backup-20261107/`. No VMEmu source changes were needed.

## Validation

Focused ABI tests cover `-O0`, `-O2` and `-Os` at 16/64 MiB. Software-interrupt
and managed-pmap tests include ordering, coalescing, capacity, teardown,
allocation-failure rollback, real timer interrupts, protection faults and exact
page/map restoration. A ten-minute, eight-worker producer/consumer test passed
with MI softclock and managed mappings enabled.

The complete candidate regression suite passed with 272 reported checks and
exit status zero. This includes the new kernel-copy recovery tests and the
existing fatal-trap and hardware-protection tests. The corrected source was
then copied into the main checkout, clean-built with the installed toolchain,
and passed the latest-stage/softint suite. `./run.sh` was also verified with
the installed VMEmu. The complete stage-51 image boots at 4 MiB as well as the
normal 640 MiB configuration.

Three separate 600-second stress runs passed at 16 MiB:

- Eight-worker CV/message/timeout load with dedicated MI softclock and PV tracking.
- Eight-worker IRQ/heap/timed-sleep load and restart of the legacy clock.
- Eight-worker CV/message/timeout load with the synchronous callout path.

Kernel-copy recovery and managed mappings were also checked with the backed-up
older compiler ABI. The ten older allocator fixtures were updated from their
obsolete stage-20 expectation to the harness's stage-32 checkpoint; all ten
focused allocation tests passed. Low-RAM checks now distinguish a loader refusal
from a later memory-startup failure and use 4 MiB for the full-image RAM smoke.

The test harness retains a five-second default observation window and accepts
`--timeout` for ordinary cases; explicitly timed clock/stress tests keep their
own deadlines. An additional main-checkout run with a two-second window passed
73 checks before its 640 MiB startup exceeded the observation window. Large-RAM
boots now preserve the normal five-second minimum in quick runs. The affected
LWP/VM group passed all seven checks with that correction; this does not alter the completed
272-check run with normal windows.

The full-suite log is `/tmp/rvm-kcopy-full.log`; the three stress logs are
`/tmp/rvm-pmap-softint-stress.log`, `/tmp/rvm-kcopy-async-stress.log` and
`/tmp/rvm-kcopy-wait-stress.log`. Main-checkout validation is recorded in
`/tmp/rvm-clean-build.log`, `/tmp/rvm-main-final-smoke.log`,
`/tmp/rvm-run-sh-final.log` and `/tmp/rvm-main-lwpvm.log`. These temporary logs
and toolchain backups should be copied elsewhere if they need to survive host
cleanup. Source changes and reproduction instructions remain in the checkout.
