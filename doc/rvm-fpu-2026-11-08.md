# NetBSD/RVM FPU and GCC integration — 2026-11-08

The [2026-11-09 libm/fenv update](rvm-libm-fenv-2026-11-09.md) supersedes the
pending fenv/libm, fixed gdtoa rounding and raw arithmetic mnemonic limitations
below. The remaining sections describe the original integration milestone.

The port now preserves the VMEmu v0000 FPU state and its installed GCC supports
native binary64 instructions with `-mfpu`. The userland builder enables this
option by default. The kernel's C code continues to use integer registers;
only the explicit MD context accessors touch the FPU.

## Compiler

The maintained sibling backend and installed `rvm-netbsd-gcc` driver/`cc1`
include `rvm-native-fpu.patch`. The previous driver, cc1 and backend files are
backed up under `/tmp/rvm-native-fpu-toolchain-backup-20261108/`.

`-mfpu` emits native add/subtract/multiply/divide, absolute value and square
root for `double` (and RVM's binary64 `long double`). It defines
`__RVM_FPU__` and `__RVM_FPU_GPR_ABI__`. `-mno-fpu` selects the existing software
arithmetic helpers. The compiler's default remains software arithmetic;
`UserBuilder` explicitly selects `-mfpu` for user code and its static libraries.
The builder's `--software-float` option permits comparison builds, which still
require the FPU context instructions in the emulator.

The calling convention is unchanged: floating values travel as raw bits in
the existing integer argument/result registers. Each native operation saves
its scratch FP registers, transfers operand/result bits through the user stack,
and restores the FP registers. No FP register is newly exposed to GCC's
register allocator. This first implementation favors ABI compatibility; direct
FP register allocation and more efficient raw memory transfers are future work.

Single precision, comparisons and integer conversions still use compiler-rt.
Those software paths retain their existing rounding/exception behavior. Native
binary64 arithmetic honors FPCR's four rounding modes and accumulates FPSR's
exception flags. Selectable C `<fenv.h>` support and complete mixed-precision
exception semantics remain unported. The gdtoa build still assumes nearest-even
rounding for formatting and parsing. Restore FPCR to nearest before using it.
The square-root compiler test uses `-fno-math-errno` to select FSqrt directly;
a complete libm, including the normal errno-setting fallback, remains future work.

Raw `.short`/`.byte`/`.quad` encodings appear in compiler output until the FHR
assemblers and disassembler gain the new mnemonic table. This also avoids
using older opcode assignments for FPushm/FMove. The required VMEmu provides
FPusha/FPopa, FPCR/FPSR and the opcode assignments in its `docs/fpu.md`.

## Kernel and process state

`struct fpreg` contains 64 raw binary64 words followed by FPCR and FPSR.
`struct trapframe` and `mcontext_t` carry this bank. Every normal user trap or
user timer interrupt saves it before allowing rescheduling; user return
restores it. Kernel LWPs use no FP registers, so no lazy owner or PCB FP context
is needed. Fork copies the saved bank; exec clears it. Signal frames include
`_UC_FPU`, and setcontext restores the saved FP state after a handler returns.

PT_GETFPREGS/PT_SETFPREGS read/write stopped user state. The kernel accepts all
raw register bit patterns, including NaN payloads and signed zero, and rejects
reserved FPCR/FPSR bits. The FPCR mask is 0x3; FPSR exceptions occupy 0x1f and
comparison flags occupy 0xf00. The emulator has sticky flags, with no enabled
FP exception traps.

The static runtime's setjmp family saves/restores all 64 FP registers and both
controls alongside integer registers and the optional signal mask. Its jump
buffer grew to 128 eight-byte slots. Rebuild programs using setjmp or ucontext:
their context layouts have changed.

## Assembler adapter corrections

Native compilation exposed two existing FHR adapter/assembler issues. The
explicit replacement for `.comm` now restores the active section, so a later
function remains executable even when GCC does not emit another `.text`.
Writable storage is also emitted before code: repeated forward absolute-memory
references in RVM GAS can otherwise create a relocation to read-only data.
This fixes gdtoa's `pmem_next` update and is covered by real compiler/object and
guest tests. The original MI library code is not reordered or edited.

The adapter folds text/data/rodata subsections into their primary sections,
retaining explicit alignment, and repeats public binding declarations beside
their definitions. FHR GAS otherwise loses some globals after section reordering.

Kernel build stamps now include the adapter sources as well as installed tool
contents, so changing these adapters also rebuilds kernel/libkern objects.

## Running and testing

```sh
./build-diskroot.sh
./run-diskroot.sh
```

Type `sh` at `rvm#` for the native NetBSD shell; `exit 0` returns to the monitor,
syncs the filesystem and remounts it read-only. See the
[stdio/shell notes](rvm-stdio-shell-2026-11-08.md) for native utilities and examples.

```sh
python3 sys/arch/rvm/tests/hardfile.py --objdir obj.rvm-diskroot \
    --diskroot --expect-accel
python3 sys/arch/rvm/tests/console.py --shell --pixels --keypad
python3 sys/arch/rvm/tests/fpu_compiler.py
```

The kernel/root fixture verifies raw banks, all controls, syscall/interrupt
return, scheduling between processes, fork inheritance, exec reset, signal
restoration and actual ptrace reads/writes including reserved-bit rejection.
The native compiler check exercises add/subtract/multiply/divide, aliased
operands, sqrt/abs, signed zero, all four rounding modes, invalid/divide-zero/
overflow/underflow/inexact flags and preservation of every FP register.
`fpu_compiler.py` compiles and executes this check at -O0, -O2 and -Os.

The existing stdio, files, signals, caches/TLB, entropy, userland script,
interactive job control and filesystem persistence checks remain enabled.
The full disk-root boot suite allows 60 seconds per boot because it executes
many static utilities and the shell integration script before the monitor.

Validation after the final assembler corrections and complete object rebuilds:

* DISKROOT_ACCEL and DISKROOT_ACCEL_DIAGNOSTIC: full startup and filesystem
  persistence across reboot at both 64 MiB and 640 MiB.
* EARLY: kernel integration, real user processes and root-device prompt at
  both memory sizes.
* Native GCC arithmetic/rounding/exception checks at -O0, -O2 and -Os.
* Interactive shell and job control at both memory sizes; keyboard, keypad
  and rendered backspace/pixel checks at 64 MiB.
* FHR private/public symbols, common storage, data alignment, forward writable
  references, weak aliases/overrides and archive-member linkage.
